# ISV 分销控制台「规格匹配」全量过一遍（isv_sku_match）设计

**日期**：2026-10-14
**状态**：脚本已实现（dry-run 冒烟通过：4183 条/210 页、3 样本开抽屉→读→关无残留）；`--apply` 试点待用户点头。
**脚本**：`automation/sourcing/isv_sku_match.py`（已建，连 9222）

> 实现补充（相对初稿）：①抽屉里的规格下拉是**自定义选择器**（`.spec-select-dropdown`，颜色/尺码 radio 组+取消/确认），读不到 1688 规格清单 → 规格数改为两级来源：DB `source_sku`（精确，~838/4183）→ 选择器 radio 组数求积（`picker_est` 估算）→ 都没有则不判计数。②关抽屉**禁用键盘 Escape**（事件到不了 iframe），只走取消按钮/关闭X/遮罩。③快捷筛选 chip 带计数后缀，前缀匹配。

## 1. 背景与目标

淘宝商品库存同步走 1688 淘分销，同步是 **SKU 规格级**的：淘宝商品每个 SKU 规格必须与 1688 货源
SKU **1:1 匹配**，否则同步对不上。分销控制台（ufuwu.1688.com ISV 容器，9222）「商品管理」列表
操作列「更多」里有「**匹配规格**」抽屉，内含平台自带的「**自动匹配规格**」按钮。

**目标**：把「已关联货源」列表（2026-10-14 实测 4183）**每个商品都过一遍**——不管当前是不是
「已匹配」，都开抽屉 → 点「自动匹配规格」→ 点「确 认」保存；修不全/对不上的记录下来人工处理。

## 2. 页面结构（2026-10-14 只读探针实测，v3.5.51）

- 列表：iframe（URL 含 `isv-container`），行 `.ant-table-row`；操作列=`编辑店铺商品|更换货源|更多`；
  「更多」下拉项=`关联多货源/取消关联/匹配规格/同步订单/删除商品/下架商品`。
- 快捷筛选：销售中(913)/仓库中(3275)/**已关联货源(4183)**/未关联货源(1)/关联货源已下架(235)/价格倒挂(62)。
  （计数随时间变，跑时以页面为准。）
- 「匹配规格」= **ant-drawer**（`position:fixed`，**勿用 offsetParent 判可见**，用 `.ant-drawer-open`）：
  - 商品信息区：店铺商品（淘宝）↔ 货源（1688，可 更换/添加货源）。
  - 规格信息表：列=`店铺商品规格 | 规格状态 | 筛选 | 关联货源规格 | 操作`；
    店铺规格单元格文本含 `预览 <规格名> 价格：…元 库存：…`；
    关联货源规格是下拉（ant-select/next-select，当前值如 淘宝「2XL 灰色」↔1688「灰色-2XL」，**顺序无关**）；
    行操作=`清除 | 添加规格 | 移除规格`。
  - 底部按钮：`取 消 | 自动匹配规格 | 确 认`。

## 3. 流程（单模式，默认 dry-run）

1. 连 9222 → ISV 容器 iframe → 「分销铺货」flyout → 商品管理 → 快捷筛选点「**已关联货源**」。
2. 逐页逐行（每行取 店铺商品ID(item_id)、货源 offerId、标题）：
   - 点「更多」→「匹配规格」开抽屉；
   - 读规格表全部行：`[{淘宝规格名, 淘宝价格, 淘宝库存, 规格状态, 当前绑定1688规格}]`；
   - 打开任一行下拉（或读 1688 侧）取 **1688 全部规格清单** → 规格数；
   - **计数校验**：淘宝 SKU 数 ≠ 1688 规格数 → 记 `count_mismatch`（附两侧明细）；
   - **重复绑定**：同一 1688 规格被 ≥2 个淘宝 SKU 绑定 → 记 `sku_duplicate`（违反 1:1，不自动改）；
   - dry-run：到此为止，点「取 消」关抽屉；
   - `--apply`：点「**自动匹配规格**」→ 等待 → 回读全部行状态：
     - 全部「已匹配」→ 点「确 认」→ `ok`；
     - 仍有未匹配 → **仍点「确 认」**（保存平台已配上的部分）→ 剩余行记 `manual_needed`（商品+淘宝规格名清单）；
   - 关抽屉 → 间隔 `--gap`（默认 10s）→ 下一行。
3. 翻页到列表末尾为止。翻页与行定位沿用列表 DOM（`.ant-table-row` + 下一页按钮），SPA 同 URL
   翻页用点按钮不用改 URL。

## 4. 报告 / 续跑

- `sku_match_report.json`（gitignore）：`items[]` 按 `item_id` 就地更新，
  `{item_id, offer_id, title, taobao_sku_count, offer_spec_count, before:{matched,unmatched[]},
    after:{matched,unmatched[]}, status, ts}`。
- `status ∈ ok / manual_needed / count_mismatch / sku_duplicate / drawer_fail / offer_delisted / dry`。
- **`count_mismatch` / `sku_duplicate` / `manual_needed` / `ok` 只在 `--apply` 阶段写入**；
  dry-run 一律记 `dry`（异常明细放 `before`/`anomalies` 字段里供预览），保证 apply 重跑会真正处理。
- 续跑默认跳过 `status ∈ {ok, manual_needed, count_mismatch, sku_duplicate, offer_delisted}`
  （这些是"已处理完"或"结论已记录"）；`drawer_fail` 与 `dry` 重跑会再来；`--force` 全量重来。
- 另出 `sku_match_manual.csv`（人工处理清单：item_id、标题、问题类型、明细），一行一问题。

## 5. 默认假设（不同意需改）

1. 范围=「已关联货源」全部商品（含当前已匹配的）；「未关联货源」「关联货源已下架」不在列表内自然跳过
   （若列表含已下架货源行则记 `offer_delisted` 跳过）。
2. 「自动匹配规格」可能重绑已匹配行——**首轮先 `--limit 1` 你盯一个商品看效果**，再放量。
3. 确认后不改价不改库存，只保存规格绑定。
4. 抽屉规格行多时（大 SKU 表）可能有滚动加载/分页，脚本需滚动到底再读（待实测）。
5. 不写 DB，报告 json+csv 即全部产物。

## 6. 长跑预估

4183 商品 ×（开抽屉~5s + 读~2s + 自动匹配~3s + 确认~2s + gap 10s）≈ **29 小时**。
`--gap` 可调小（如 5s ≈ 20 小时）；支持断点续跑分多晚跑。跑法用 `nohup … python -u` 后台 + 日志。

## 7. 已知坑（沿用 AGENTS）

- 抽屉是 fixed 定位，可见性判断用 `.ant-drawer-open`，别用 offsetParent（本次踩过）。
- 侧栏收起态菜单要 `hover(force=True)` + 真点击 flyout 项；SPA 筛选 chip 跨会话残留 → 每次先「重 置」。
- ISV 容器勾选/复杂控件要真实鼠标点击；「确 认」后回读列表行状态做校验。
- 风控/滑块迹象 → 存报告停轮（exit 3）；CDP 掉线按 `run_cat_v2.sh` 的自愈思路另行处理。
